# Weave production migration release

This repository owns the shared Platform migration history. The Weave application
repository supplies candidate SQL; a candidate there is not a hosted migration.
This release reconciles seven already-applied records and adds six reviewed
Weave candidates. Website application code and dependencies are unchanged.

## History reconciliation

Platform already records these versions. Do not apply them again:

- `20261108031732_weave_certified_private_access`
- `20261108032041_weave_platform_runtime_logins`
- `20261109045842_weave_matching`
- `20261109050006_weave_project_index`
- `20261109050112_weave_matching_vectors`
- `20261110040828_weave_project_oauth`
- `20261110040924_weave_project_workspaces`

The six non-credential records were restored from their recorded applied SQL.
The runtime-login record deliberately has a credential-free replay definition:
new environments create those roles as `NOLOGIN` and provision credentials
separately. Historical operator password literals are never copied into Git.
This does not change existing Platform logins or its migration records.

## New migrations

These files match the candidates in Weave release `1914fe8` byte for byte:

1. `20261112184035_weave_team_content`: private team saving, checked-document
   validation and workspace-authorized matching. Closes direct client matching RPCs.
2. `20261112184037_weave_public_evidence_snapshot`: bounded public evidence for
   on-device ranking without sharing a team's private query.
3. `20261112184038_weave_project_discovery`: restricted workspace/setup discovery.
4. `20261112184040_weave_workspace_invites`: pending claims and explicit approval;
   an invitation link alone grants no team access.
5. `20261112184042_weave_support_publication`: separate publication reviews,
   durable requests and withdrawal bookkeeping. Does not enable public publishing.
6. `20261112184045_weave_open_ended_sharing`: undated shares remain eligible until
   edited, closed or withdrawn. Does not enable hybrid retrieval.

## Operator sequence

The user approved this owner release and these six migrations on 12 November 2026.
Apply only after the owner PR is reviewed, checks pass and it is merged. Use the
merged owner checkout and verify the project ref before each hosted command.

The checked CLI version is 2.122.0; use its `--help` when using another version.
These commands select Platform explicitly and do not include seeds, role files,
Vault changes, authentication settings or credentials:

```sh
supabase migration list --project-ref ztygpuzldujfsqrubxic
supabase db push --project-ref ztygpuzldujfsqrubxic --dry-run --skip-vault
supabase db push --project-ref ztygpuzldujfsqrubxic --skip-vault
supabase migration list --project-ref ztygpuzldujfsqrubxic
```

The dry run must list exactly the six new versions above. Stop if any historical
version would be reapplied, another version is pending, or the remote has changed.
Use existing authorized CLI authentication; never put a database password in a
command, file, commit or log. Check migration history and grants after application.
Do not substitute a second migration history generated by another repository.

Keep `private.weave_matching_retrieval_settings.hybrid_enabled` false. The API's
dedicated runtime roles, state/signing keys, Certified consent, Auth callbacks and
production app configuration are separate operator steps. Schema installation does
not establish a working sign-in or real-user acceptance.

## Verification and recovery

The disposable SQL baseline models Certified identities, JWT expiry, banned and
anonymous users. CI uses Supabase PostgreSQL 17 with pgvector and creates a clean
database from `template0`, avoiding the image's preinstalled Auth schemas. All
website SQL tests still run, including steward access and email-delivery boundaries.

Local proof: all 22 migrations replayed; all nine owner SQL suites passed; website
syntax checks, 88 fixture tests and HTTP smoke passed. The exact CI image, TCP
password authentication and fresh-database bootstrap were exercised separately.
Weave's separate local PostgreSQL suites passed 28 tests covering discovery,
invitations, private team saves, two-owner share/edit/withdraw, public snapshots,
index retrieval and public support lifecycle. They use synthetic providers and
identities; they are not real Certified or hosted Auth acceptance.

An independent review read all 13 restored/new migration files and the fixture/CI
changes without actionable findings. Hosted application and browser acceptance
must be recorded separately after execution.

Each migration is transactional. A failed migration rolls back; diagnose it before
retrying. After successful team writes, disable project actions and repair forward
through a reviewed migration. Do not drop saved initiatives, grants or shared
Platform data as a rollback. The prior preview's direct matching RPC path is
intentionally revoked; the workspace-aware Weave API must accompany this schema.
